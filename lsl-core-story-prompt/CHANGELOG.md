# CHANGELOG · lsl-core-story-prompt

## v0.1.0（2026-11-07）第一版

**来源**：《梦浮生》第 01 集（情感，9:16，120 秒，7 段）的调度稿试做 → 核心落地示例 → 方法论研究 v0.1 → 用户四条建议 → 剧情核心工作台原型（深色 v1 → 浅色导演同款 → 阶段卡描边修正）→ 用户说“固定这次的界面基线”。

**方法（v0.1）**
- 六步：能拍的核心 → 贯穿物去向 → 人物 → 场景 → 按秒节拍（最后一列“核心走到哪”）→ 回头检查。
- 两层核心：集核心 → 段核心（段核心是集核心的一步，按顺序连读走完集核心）。
- 能拍测试：人、东西、反复的动作、最后的变化；禁用词 9 个。
- 候选每次 3 个、方向拉得开；人的标注是下一轮生成的硬条件；人可以自己写。
- 剧本写死的不改；额外设计全部进提案，人留或删。
- 时间写法“（a–b）N 秒”；歌词字幕只写“（剧本字幕）”。
- 六类剧本的核心句式模板（情感已验证，其余五类待验证）。
- 输出“剧情核心提示词”固定格式＋交给 director-video-prompt 的开始提示词＋交接约定。

**质检（新）**
- 四级：Q0 页面自动检查、Q1 案例质检（10 硬项 + 6 软项）、Q2 交接质检（含 A/B 对照）、Q3 版本质检（回归）。
- `tools/qa_check.py`：读工作台档案，自动查能查的项，出 Markdown 报告。

**界面基线 CSP-UI-1（新）**
- 剧情核心工作台，和导演界面 UI-7 同一套，浅色锁定。
- 12 个节点（LangGraph 思路）、四张阶段卡、四页签、段卡片、版本记录（回到 / 分叉）。
- 数据存在页面数据库（db），页面自己调 Claude（sample），导出 .md（downloads）。
- `tests/` 假数据全流程 27 条全过；6 张截图。

**已知没做**：多集剧的全剧核心一层；质检页签；节拍表 AI 风险列；五类模板的真实剧本验证。
