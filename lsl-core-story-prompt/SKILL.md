# lsl core story prompt v0.1.0（故事核心提示词）

本次回复第一句写：**本次使用 lsl-core-story-prompt v0.1.0**。

这个 skill 放在**剧本**和**导演 skill（director-video-prompt）**之间。它不拆镜头、不写投喂版，只做一件事：在导演动手之前，先把“这部戏怎么演、按时间怎么排”定下来——具体到人、物、场景、秒数——让人看得懂、能参与，再整包交给导演 skill，当作已经确认的事实。

- 方法：本文件第 2—7 节（完整写法和例子在 `references/method.md`、`references/templates.md`、`references/example-mengfusheng.md`）。
- 输出：第 8 节（细则 `references/output.md`）。
- 质检：第 9 节（细则 `references/qa.md`，脚本 `tools/qa_check.py`）。
- 界面：第 10 节（基线 `ui-baseline/`，当前 **CSP-UI-1**）。
- 项目规矩：项目文件夹里的 `项目宪法.md`（有就先读）。

文件夹里少了 `references/`、`ui-baseline/` 时（比如只装了这一个文件），按本文件做；界面页面从基线链接读（第 10 节）。

## 1. 开工前

1. 有项目文件夹（`00故事核心提示词/`）就先读 `进度.md`，看停在哪、这次走哪条主线；规则有疑问读 `项目宪法.md`。
2. 要齐四样东西，缺的才问：**剧本原文**、**目标时长和画幅**（例如 9:16、120 秒）、**剧本类型**（情感 / 带货 / 玄幻打斗 / 悬疑反转 / 喜剧 / 多集；拿不准就自己判断并说出来）、**交付方式**（工作台网页还是只要文字，默认工作台）。
3. 剧本里引用歌词的字幕，一律只写“（剧本字幕）”，不复述歌词原文。

## 2. “核心”是什么，为什么少不了

**核心是一把挑演法的尺子。** 剧本只写“发生了什么”，不写“怎么演”；同一句话至少有两种都说得通的演法。核心决定挑哪一种，挑出来的结果全部落到人、物、场景和秒数上。

没有核心的三个实际麻烦：

1. **一句话有好几种演法，只能凭感觉挑。** 例：“二人紧紧相拥，彼此许诺平安归来”——常见演法是抱着哭；按《梦浮生》的核心，她先忙着替他扣扣子，不哭，他的许诺听不见，因为以后她只能靠信。
2. **段与段接不上。** 即梦每段 ≤15 秒、分开生成，不共享记忆。每段各挑各的“最好演法”，拼起来是几个互不相干的好镜头。核心就是每段都要守的同一条线。
3. **不知道删什么。** 时长装不下所有好主意，按核心判断加不加。

**主旨不是核心。** 主旨是拍完以后观众心里留下的东西（缅怀、团圆），里面没有一个词能直接拍；核心回答的是“用什么看得见的东西把主旨演出来”。

**两层核心：**

- **集核心**：整集一句。
- **段核心**：每段一句，必须是集核心里的一步；各段按顺序连读，应当正好把集核心走完。
- 多集剧再加一层“全剧核心”，每集的集核心是它的一步。

## 3. 能拍测试（每一句核心都要过）

一句核心必须写得出四样，缺一不可：

| 项 | 问 | 《梦浮生》集核心 |
|---|---|---|
| 人 | 谁 | 她（从二十出头到八十多岁） |
| 东西 | 一件看得见、拿得到的东西 | 信 |
| 动作 | 反复做的动作 | 写、寄出、被退回 |
| 变化 | 最后变成什么 | 从寄不到，到亲手送到 |

- **禁用词**（拍不出来）：爱情、坚守、思念、家国、情怀、命运、灵魂、深情、感动。出现就改写成手上的动作或看得见的结果。
- 情绪不写形容词，写手上在做的事和画面里看得见的结果。
- 《梦浮生》集核心：**她把一辈子写进寄不出去的信里；唯一寄回来的一封是他的死讯；最后她带着那封信跨海，亲手交给了他。**

## 4. 流程：12 个节点（LangGraph 思路）

状态＝一份剧情档案；节点＝每一步；人工节点停下来等人；每步跑完存一版（检查点），可以回到任意一版或分叉。

| # | 节点 | 谁做 | 产出 |
|---|---|---|---|
| 01 | 读剧本 | Claude | 按剧本自己的分段拆开，段号 01A、01B…，起止秒首尾相接，每段一两句写发生了什么，台词保留原话 |
| 02 | 划分已定和空着 | Claude | 已定：剧本写死的事件、台词、字幕、时长、地点（一句不改）；空着：谁先动、怎么演、东西在哪、最后去哪（要设计） |
| 03 | 集核心候选 | Claude | 3 个方向真的拉得开的候选（见第 5 节） |
| 04 | 你选集核心 | **人** | 选一个、标注、或自己写 |
| 05 | 段核心候选 | Claude | 每段 3 个候选，写清是集核心里的哪一步 |
| 06 | 你选段核心 | **人** | 逐段选、标注、自己写 |
| 07 | 能拍测试（连读） | Claude | 各段核心按序连读：是不是集核心的一步、有没有跳步重复断掉、每句能不能拍 |
| 08 | 四张表 | Claude | 物件、人物、场景、节拍＋全片规矩＋提案（见第 6 节） |
| 09 | 自动检查 | 规则 | 秒数接不接、物件有没有去向、每拍有没有推进核心、怎么演里有没有禁用词 |
| 10 | 你取舍提案 | **人** | Claude 在剧本上额外加的每条设计：留 / 删 |
| 11 | 剧情核心提示词 | 合成 | 固定格式（第 8 节） |
| 12 | 交给导演 skill | **人** | 复制开始提示词到新对话 |

**条件边：**

- 集核心一改，各段段核心标“待重算”。
- 段核心一改，能拍测试和四张表标“待重测 / 待重写”。
- 自动检查有漏洞，就带着漏洞清单退回 08 重写。
- 候选都不满意，就按标注和要求重新生成（回到 03 或 05）。

## 5. 候选怎么写

- **每次 3 个**，方向要真的拉得开，不是同一个意思换种说法。集核心默认三向：偏情感和物件 / 偏人物的日常习惯 / 偏主旨。按类型调整（第 7 节模板）。
- 每个候选带：`text`（≤60 字）、人、东西、动作、变化、`step`（段核心写“是集核心里的哪一步”）、`effect`（“选它会变：……”，说清会改哪几段、哪几秒）。
- **好核心的四条标准**：能拍；贯穿全片（每一段都用得上）；和剧本主旨接得上；几个候选之间拉得开。
- **人的标注是硬条件**：人在候选文字上选中几个字写意见（例：“松开了自己写的那一封”→“松开时手指还张着，像还想抓住”），下一轮生成必须照做，意思不能丢；人自己写的核心可以借方向。
- 剧本写死的事件、台词、字幕、时长不能改；额外加的东西都要能删（进提案）。

## 6. 四张表（列名固定）

1. **贯穿物去向**：贯穿全片的 3—6 样东西。每件写清它在核心里是什么、按秒的出现（第几秒、在谁手上、当时什么样）、**最后在哪（必须交代）**；配泳道图。
2. **人物**：每段一行——几岁 / 这一段想要什么 / 手上在做的事 / 不做的（如“不哭”）/ 对方以什么样子在场。多人戏改成按人列，每人一句自己的“脊柱”（整部戏想要什么）。
3. **场景**：每个地方在核心里干什么用 / 出现在哪几段 / 里面放什么、东西在哪。说不出在核心里干什么的地方，就不加或给得很短。
4. **节拍（按秒）**：时间 / 场景 / 人 / 物 / 怎么演 / **核心走到哪** / 张力 0—10。首尾相接盖满全片，每拍 2—8 秒（快节奏剧允许一拍列 2—4 个小动作）。**只写到节拍，不拆镜头**，拆几镜交给导演 skill。

另外写：**全片规矩** 4—8 条（如“同一张桌子同一机位”“全片只哭一次”）；**提案**——Claude 在剧本上额外加的每条设计，写清在哪、为什么，每条都能删。

时间一律写成“（a–b）N 秒”，例：（98–100）2 秒。

## 7. 核心句式（按类型）

共同骨架：**同一件东西反复出现，每次状态不同，最后一次翻过来。**

| 类型 | 句式 | 贯穿物通常是 | 多查什么 |
|---|---|---|---|
| 情感、怀念 | 【人】用【东西】反复【动作】，最后【东西】到了【哪里】或变成了【什么】 | 信物、照片、旧东西 | 哪里收、哪里放；“只哭一次”这类规矩有没有破 |
| 电商带货短剧 | 【人】被【看得见的麻烦】反复卡住，【产品】让麻烦第一次消失，【旁人】的态度翻过来 | 产品＋麻烦的证据 | 产品出现前麻烦至少出现两次；卖点落在动作上，不靠台词 |
| 玄幻、打斗 | 【人】每用一次【力量】就付出【代价】，最后他【放弃、用尽或交出】它 | 武器、伤、印记、法器 | 代价看得见、一次比一次重；打斗方向和轴线 |
| 悬疑、反转 | 观众以为【东西】说明 A，最后发现它说明 B | 线索物 | 每次出现同时说得通 A 和 B；不提前泄底 |
| 喜剧 | 【人】越想藏住或甩掉【东西】，它越冒出来，最后在最糟的时候全露出来 | 被藏的东西 | 每次“露”都比上一次更糟 |
| 多集连续剧 | 全剧一句大核心，每集一句小核心；小核心是大核心里的一步 | 跨集流转的物件 | 物件跨集去向；每集结尾停在大核心哪一步（钩子） |

v0.1.0 只有“情感”用真实剧本验证过（《梦浮生》），其余五类是待验证的模板。

## 8. 输出：剧情核心提示词

固定格式（工作台第 11 节点自动合成，对话模式照这个写）：

```
【剧情核心提示词】<剧名和集数>
集核心：……

段核心：
- 01A <段名>（a–b）N 秒：……
（每段一行）

全片规矩：1. …… 2. ……
贯穿物去向：- <物>（在核心里是什么）：第 N 秒 …… → 第 N 秒 ……；最后：……
人物：- <段> · <几岁>：想要……；手上做的事：……；不做：……；他：……
场景：- <场景>（出现在）：在核心里干什么。放什么、东西在哪
节拍（按秒）：- （a–b）N 秒｜场景｜人｜物｜怎么演｜核心：……
保留的导演提案：- <在哪>：……
人工标注（原话）：- <段>“<选中的字>” → <意见>

交接：以上为已确认的事实，导演 skill 写详稿和投喂版时不重新决定；新的想法只能标“提案”。
```

**交给导演 skill 的开始提示词**（第 12 节点）：

```
/director-video-prompt
项目：<剧名>。剧本见附件。
目标：即梦 Seedance 2.5，单段 ≤15 秒，图片写 @图片N。
本次重点：按下面的剧情核心提示词写导演详稿和投喂版，里面的决定当作已确认的事实。

<剧情核心提示词全文>
```

## 9. 质检（交给导演 skill 之前必须过）

四级，细则见 `references/qa.md`：

- **Q0 页面自动检查**（节点 09，每次写完四张表自动跑）。
- **Q1 案例质检**：每个剧本交给导演 skill 前。
  - 硬项 10 条，全过才放行：事实不改、集核心能拍、段核心能拍、连读成立、秒数盖满、每拍推进核心、物件有去向、标注落实、提案取舍、版权（歌词只写“（剧本字幕）”）。
  - 软项 6 条，不过就记进方法论台账：具体度、场景有用、收放规矩、节拍密度、AI 风险、人的打分。
  - 用 `tools/qa_check.py` 跑能自动查的项，其余人工核对；写成 `案例/<编号>/质检报告-Q1-vNN.md`。
- **Q2 交接质检**：导演 skill 出详稿后，抽查有没有改掉段核心、物件去向对不对、规矩有没有破、新加的东西有没有标提案。A/B 对照也记在这里。
- **Q3 版本质检**：skill 发新版前，拿全部已完成案例回归，界面改了还要跑 `ui-baseline/tests` 全过，用户点头才发。

## 10. 界面基线 CSP-UI-1（剧情核心工作台）

**当前基线：CSP-UI-1**（2026-11-07 定）。清单、数据结构、交互规则见 `ui-baseline/CSP-UI-1.md`，截图在 `ui-baseline/screenshots/`。

- **和导演界面 UI-7 同一套**：浅色（锁浅色），单栏卷轴。
  - 页首：剧名 → 这一集的核心（大字）→ 现在停在哪 → 四张阶段卡 → 运行下一步 → 版本记录。
  - 吸顶四页签：集核心 / 段核心 / 四张表 / 剧情核心提示词，加段号跳转。
  - 段核心页：每段一张卡片，没选的展开候选，选好的收起成一句大字。
- **用法**：
  1. 把 `ui-baseline/web/workbench.html` 用 Artifact 发布，`capabilities: {"db": {}, "sample": {}, "downloads": true}`。同一个项目以后用同一个链接更新。
  2. 用户在页面里点“新建项目”粘贴剧本；页面自己调 Claude 跑 AI 节点（第一次点时请用户同意）。
  3. Claude 也可以用 ArtifactData 直接读写数据库：`projects/<id>` 存 `{title, updatedAt, json}`，`json` 是整份档案；`projects/<id>/checkpoints` 存每一版。
  4. 质检时用 ArtifactData 读出 `projects/<id>`，交给 `tools/qa_check.py`。
- **没带 `ui-baseline/` 时**：页面代码从现行基线页 https://claude.ai/artifact/Fq7iWeUHqQ8WKvh35uLVCo 读（Artifact read），复制成新文件发布，不在那一页上直接改。
- **不改的规矩**：项目里不改页签、模块、按钮名、配色，不重新设计样式。觉得要改，先照基线交，把用户原话记进台账（U 类），攒够了由维护者升 CSP-UI-2，升级要跑 `ui-baseline/tests` 全过、截图重拍。
- **改基线时守住两条**：
  - 阶段卡的棕色描边跟着“现在看的是哪一页”走，“等你 / 运行中”用小标签标。
  - 时间一律写“（a–b）N 秒”。

## 11. 两种交付

- **工作台（默认）**：适合要参与、要来回改的情况。
- **只要文字**：Claude 在对话里按 01—12 走，人工节点用选择题问用户，四张表写成文档或 `.md`，最后给出第 8 节格式的提示词；质检照样做。
- **剧本本身已经很细时**：只做定核心（01—07）、贯穿物去向（08 里只写物件表）和检查（09），其余照剧本，并告诉用户为什么跳过。

## 12. 红线

1. 剧本写死的事件、台词、字幕、时长不改；额外加的全进提案、都能删。
2. 不复述歌词原文；不照搬受保护作品的角色和画面。
3. 不替导演 skill 拆镜头、不写投喂版。
4. 人工节点不替人拍板：没选就停下来等，不要“默认选 A 往下走”（用户明确说“你定”除外，并写明是 Claude 定的）。
5. 密钥、口令不进任何文件；推送仓库绝不强推。
6. skill 升级、界面基线升级都要用户点头。

## 13. 还没解决的问题（每条先有暂定做法）

1. **快节奏、密镜头剧本**：一拍允许 2—4 个小动作，仍不拆镜头。
2. **多人群戏**：核心管全片，每个主要人物一句“脊柱”。
3. **剧本要求和核心打架**：事件和台词不动；节奏、景别这类可调的跟核心走；冲突列给用户定。
4. **AI 拍不稳的动作**（手停在半空、把信读两遍）：节拍表加“AI 风险”提醒，高风险的动作备一个简化写法。
5. **剧本已经很细**：见第 11 节。
6. **核心选得好不好**：用第 5 节四条标准，加 Q1 的人工打分。

这些在跑新类型剧本时逐条验证，结果记进方法论台账（项目文件夹 `方法论台账.md`）。

## 14. 版本与维护

- 版本号 `主.次.补`：
  - 补：措辞、修错、补例子。
  - 次：方法规则变了、新增或改了类型模板、界面基线升级。
  - 1.0.0：六类剧本都跑过、Q3 回归全过。
- 每次发版写 `CHANGELOG.md`，同步改本文件标题的版本号；项目文件夹里更新 `进度.md`、`方法论台账.md`，再更新推送包（`推送/msg/vX.Y.Z.txt`）。用户双击 `推送/双击推送.bat` 推到仓库。
- 方法论台账的条目从“候选”升为“采纳”的条件：在 ≥2 种类型剧本上成立，或用户明确拍板。采纳后写进本文件并升次版本；废弃也写理由，不删记录。
