# 质检规则（v0.1）

目的只有两个：**不把有漏洞的剧情核心交给导演 skill；把每次发现的问题变成方法论的养料。**

质检分四级，越往后越大：

| 级 | 什么时候 | 谁做 | 查什么 | 放行条件 |
|---|---|---|---|---|
| Q0 页面自动检查 | 每次写完四张表 | 工作台（节点 09） | 秒数、物件去向、每拍核心、禁用词、未选段 | 没有漏洞，或者带着漏洞退回重写 |
| Q1 案例质检 | 每个剧本交给导演 skill 之前 | Claude（`tools/qa_check.py` ＋ 人工核对）＋ 用户打分 | 下面 10 条硬项、6 条软项 | 10 条硬项全过 |
| Q2 交接质检 | 导演 skill 出详稿和投喂版之后 | Claude ＋ 用户 | 导演有没有守住剧情核心；A/B 对照 | 没有违背，或违背都已改回、或标成提案经用户同意 |
| Q3 版本质检 | skill 或界面基线发新版之前 | Claude ＋ 用户点头 | 回归测试集、界面测试 | 回归全过、用户点头 |

## Q1 案例质检

### 硬项（H，全过才能交给导演 skill）

| 编号 | 项 | 怎么查 | 自动 |
|---|---|---|---|
| H1 | 剧本事实不改 | 段数、每段起止秒和剧本一致；台词和字幕原话一字不差；剧本写死的事件都在节拍里出现 | 半自动（秒数和引号里的原话） |
| H2 | 集核心能拍 | 人、东西、动作、变化四项都有；没有禁用词 | 自动 |
| H3 | 段核心都能拍 | 每段都选了；每句四项都有、没有禁用词；你写的核心人工对一遍 | 自动＋人工 |
| H4 | 连读成立 | 能拍测试（节点 07）跑过、结果是最新的；提出的问题都处理了（改了或写明不改的理由） | 自动看状态，人工看处理 |
| H5 | 秒数盖满 | 节拍从 0 秒开始、首尾相接、停在全片时长；没有空档和重叠 | 自动 |
| H6 | 每拍推进核心 | 节拍表“核心走到哪”一列没有空格 | 自动 |
| H7 | 物件有去向 | 每件贯穿物都写了最后在哪 | 自动 |
| H8 | 标注落实 | 每条人工标注，在最终选定的核心或四张表里能找到对应的改动；没采纳的写明理由 | 人工（脚本列出清单） |
| H9 | 提案都取舍过 | 每条提案都有“留 / 删”；剧本外加的设计没有混进正文 | 自动 |
| H10 | 版权 | 歌词字幕只写“（剧本字幕）”；没有复述受保护作品的台词、角色、标志画面 | 半自动（列出全部字幕和引号让人看） |

### 软项（S，不过不拦，但要记进方法论台账）

| 编号 | 项 | 怎么查 | 合格线（暂定） |
|---|---|---|---|
| S1 | 具体度 | “怎么演”一列，写的是看得见的动作和结果，不是形容词情绪 | ≥ 80% 的拍是动作 |
| S2 | 场景有用 | 每个场景都说得出在核心里干什么 | 100% |
| S3 | 收放有规矩 | 人物表“不做的”里至少有一条被写成全片规矩（如“全片只哭一次”），且节拍里没破 | 有且没破 |
| S4 | 节拍密度 | 每拍秒数落在这一类型的参考范围（`templates.md`） | ≥ 80% 的拍在范围内 |
| S5 | AI 风险 | 拍不稳的动作（手停在半空、读两遍、细小表情）有没有备简化写法 | 有标出来 |
| S6 | 人的打分 | 用户看完四张表打 1—5 分：“像不像我要的戏” | ≥ 4 分 |

### 怎么跑

1. 用 ArtifactData 读工作台数据库 `projects/<项目id>`，存成 JSON 文件（字段 `json` 是整份档案）。
2. `python3 tools/qa_check.py <文件> --out 案例/<编号>/质检报告-Q1-vNN.md`：脚本查完能自动查的项，其余标“人工核对”并列出要看的东西。
3. Claude 逐条补人工核对的结论，问用户要 S6 打分。
4. 结论写在报告最上面：**放行 / 不放行（差哪几条）**。不放行就回工作台改，改完重新跑一版报告（vNN 加一）。
5. 每条不过的项、每条用户标注，按“是剧本的问题、操作的问题，还是方法的问题”分类；方法的问题进方法论台账。

## Q2 交接质检

导演 skill 出了详稿和投喂版以后，对着剧情核心提示词抽查：

| 编号 | 项 | 怎么查 |
|---|---|---|
| D1 | 段核心没被改 | 详稿每段的叙事和段核心一致，没有换成别的演法 |
| D2 | 物件去向一致 | 投喂版里贯穿物的出现、位置、最后去向和物件表对得上 |
| D3 | 规矩没破 | 全片规矩（如“只哭一次”“同一张桌子同一机位”）在逐镜里都守住 |
| D4 | 新东西标了提案 | 导演 skill 额外加的内容都标“提案”，没当事实写进去 |
| D5 | 秒数对得上 | 投喂版每段的秒数和节拍表的段落起止一致 |

**A/B 对照**（同一个剧本、同一段，A 直接给导演 skill，B 先过剧情核心）：记三件事——用户要改几处、改的是不是同一类问题、哪一版段与段接得更好。结果写进案例卡，进方法论台账。

## Q3 版本质检

skill 或界面基线发新版之前：

1. **回归测试集**＝所有做完 Q1 的案例（存在 `案例/` 里的档案 JSON）。
   - 新版本改了方法规则：挑受影响的步骤重跑（至少一个旧案例），新旧结果并排给用户看。
   - 至少把全部旧档案再过一遍 `qa_check.py`，硬项结果不能变差。
2. **界面基线改了**：`ui-baseline/tests` 全过（假数据全流程、阶段卡和页签同步、400 像素手机宽度不横向滚动），截图重拍，`CSP-UI-N.md` 写清和上一版的差别和用户原话。
3. `CHANGELOG.md` 写清这一版改了什么、为什么、来自哪条台账。
4. 用户点头，才更新推送包、推送。

## 质检报告格式

见项目文件夹 `质检/质检报告模板.md`。每份报告最上面三行：**结论**（放行 / 不放行）、**版本**（skill 和界面基线）、**档案**（工作台链接和项目 id，或档案文件）。
