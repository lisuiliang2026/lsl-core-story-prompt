## 二、和导演界面 UI-7 共用的东西

两个页面要像同一个产品，下面这些照导演界面（director-video-prompt 0.9.6 的 `ui-baseline/engine/web/pre.html`）：

- **颜色**：
  - 底和面：底 `#eef1ee`、卡片 `#fbfcfa`、凹面 `#e3e8e3`。
  - 文字和线：字 `#1b211e`、次要字 `#58645d`、线 `#cdd5cf`。
  - 金色：标签 `#8a5f0e`，金色浅底 `#f1e3c4`（沙色条）。
  - 墨绿：主按钮 `#2f6450`，浅底 `#d9e9e0`。
  - “需要你决定”：浅底 `#fbe7d6`，字 `#8a3b0c`。
- **字体**：
  - 标题、核心句：Noto Serif SC。
  - 正文：Noto Sans SC。
  - 秒数和段号：IBM Plex Mono。
- **部件**：
  - 页首：小标题行、大标题、说明。
  - 吸顶栏：黑底选中的分段页签，加一排圆钮跳转（当前的墨绿实心）。
  - 左侧细刻度目录。
  - 段卡片：吸顶段头、沙色条、“需要你决定”橙底框。
  - 定义表：金色标签加正文。
  - 版本记录：可折叠。
  - 其他：提示词灰底块、页底状态行、黑色圆角提示条。
- **浅色锁定**：页面一打开就设 `data-theme="light"`，系统是深色也不翻（用户要浅色）。深色变量保留在样式里，只在显式设 `data-theme="dark"` 时用。

## 三、模块清单（自检逐项查）

1. **页首**
   - 小标题行，写上秒数和段数；右上是项目下拉和“新建项目”。
   - 剧名。
   - **这一集的核心**（大字衬线），带能拍测试四项标签：人、东西、动作、变化；右上“改集核心”。
   - 一句话写现在停在哪一步，后面跟已经定了什么。
   - **四张阶段卡**：集核心 / 段核心 / 四张表 / 剧情核心提示词。
     - 每张有编号、状态（等宽金色字）、它包含的节点和状态圆点，以及一条条件边说明。
   - “运行下一步”按钮（文字按下一步变，见第五节），加一句操作说明。
   - 版本记录（折叠）：每版可以“回到这一版”和“分叉”。
2. **吸顶栏**
   - 四页签，有等你处理的那页带金色小点。
   - Claude 运行中时显示墨绿运行条：字数实时跳，带“停止”。
   - 跳转圆钮：段核心页是段号带 ✓ ● ↻ 状态，其他页是小节名。
3. **集核心页**
   - 集核心候选：需要你决定框；候选 A/B/C 卡片；标注；自己写；按要求重新生成；换一批。
   - 剧本分段与节奏：张力曲线，标最高两处；七段时长条，点了跳到那一段；分段表；剧本原文折叠。
   - 已定和空着：两栏。
4. **段核心页**
   - 每段一张卡片：段号、段名、（a–b）N 秒、状态标签；候选数和标注数。
   - 沙色条放这一段的剧本原文。
   - 没选的段：展开候选和输入框。
   - 选好的段：收起成一句大字，能复制，也能点“看候选、改选”。
   - 集核心改过的段：显示“待重算”框。
5. **四张表页**（段核心没选完时，只显示“还差哪几段”和“去选段核心”）
   - 能拍测试：集核心加各段核心连读，下面是结论和问题表（可以跳到那一段）。
   - 贯穿物去向：泳道加时间点。
   - 人物、场景、节拍表：“核心走到哪”空着的格子标橙色“空着”。
   - 全片规矩。
   - 自动检查：漏洞一条条列成橙底框，可以“带着这 N 处漏洞让 Claude 重写四张表”。
   - 你取舍提案：每条留 / 删，加“剩下的都留”。
6. **剧情核心提示词页**：提示词全文（复制、下载 .md）；交给导演 skill 的开始提示词（复制，复制后记“已交接”）。
7. **每页底部**：“下一步”框，写下一步是什么、谁来做，带按钮。
8. **页底**：状态行，写依据的方法版本和界面基线。
9. **手机**：400 像素宽不横向溢出；跳转圆钮单行横滑；段头在窄屏不吸顶；阶段卡两列。

## 四、交互规则（改基线时不能丢）

1. **阶段卡的棕色描边跟着“现在看的是哪一页”走**；点阶段卡或点页签都同步。流程停在哪一步，用卡片右上的小标签标：“等你”（金色），“运行中”（墨绿）。
2. **段号跳转圆钮**带状态：✓ 已选、● 等你选、↻ 待重算。当前所在段是墨绿实心。
3. **选好一段**：卡片收起成大字，页面滚到下一个没选的段，提示条写“01E 定了，接着看 01F”。全部选完，提示去四张表。
4. **标注**：先在候选句子里选中几个字，点“标注”，选中的字会自动带进表单；保存后在句子里用金色底线标出来；标注是下一次重新生成的硬条件。
5. **自己写**：写进输入框，点“存为我写的核心”，变成一个“写”字候选，可以选。
6. **按要求重新生成**：把输入框的要求和本段全部标注一起发给 Claude；成功后清空输入框，失败保留。
7. **运行下一步**：
   - 找第一个没完成的节点：是 Claude 的就跳到那页并开跑；是人工的就跳到那页、滚到那一处，提示“轮到你”。
8. **条件边**：
   - 集核心一改，各段段核心标“待重算”。
   - 段核心一改，能拍测试和四张表标“待重测 / 待重写”。
   - 检查出漏洞，可以带着漏洞清单重写四张表。
9. **检查点**：每一步跑完自动存一版（最多显示最近 12 版）。“回到这一版”会另存成新的一版，“分叉”会复制成新项目，原项目不动。
10. **时间写法**一律“（a–b）N 秒”。
11. **歌词字幕**只写“（剧本字幕）”（Claude 的提示词里写死了这条）。

## 六、数据（db 能力）

- **发布时声明**：`capabilities: {"db": {}, "sample": {}, "downloads": true}`。
- **`projects/<项目id>`**：`{title, updatedAt, json}`；`json` 是整份档案的 JSON 字符串。
- **`projects/<项目id>/checkpoints/<自动id>`**：`{n, label, at, json}`。页面按 `n` 倒序取 12 条。
- **档案字段**：
  ```
  {v, title, duration,
   script:{raw, segments:[{code,name,a,b,text}]},
   split:{fixed:[{text,seg}], open:[{text,seg}]},
   ep:{candidates:[候选], chosen, annotations:[{cand,quote,note,at}]},
   seg:{<段号>:{candidates, chosen, annotations, basedOn:<当时的集核心原文>}},
   test:{ok, summary, issues:[{code,problem,fix}], basedOn:<段核心指纹>},
   tables:{rules, props:[{name,meaning,events:[{t,what}],end}], people:[{seg,age,want,doing,notDoing,him}],
           scenes:[{name,role,segs,contents}], beats:[{a,b,scene,people,objects,acting,core,tension}],
           proposals:[{id,text,where,why}], basedOn, at},
   checks:{issues:[{where,text,fix}], basedOn:<tables.at>},
   decisions:{<提案id>:"keep"|"drop"}, curve:[[秒,张力]], handedOff, updatedAt}
  ```
- **候选的字段**：`{id, tilt?, text, person, object, action, change, step, effect, own?}`。用户自己写的那个 `own:true`，`id` 是 W1、W2……
- **节点状态不存库**：每次从档案算出来。“待重算”靠 `basedOn` 和当前的集核心、段核心比对。
- **Claude 用 ArtifactData 读写**：
  - 写样例：`projects/mengfusheng`，再写 `projects/mengfusheng/checkpoints/c01…c10`。
  - 读来质检：`get projects/<id>`，交给 `tools/qa_check.py`。
- **浏览器本地**只记上次打开的项目（`jqhx.pid`）。

## 七、Claude 调用（sample 能力）

- **调用方式**：每个 AI 节点都调一次 `sample.json(提示词, {signal, modelTier, cache, onText})`。
  - 换一批和重新生成时 `cache:false`。
  - 四张表用 `modelTier:"complex"`，其余用 `"default"`。
- **提示词开头**：固定是方法规则 7 条，原文在 `workbench.html` 的 `METHOD`。
  - 剧本事实不改。
  - 能拍测试。
  - 段核心是集核心的一步。
  - 不写形容词。
  - 标注是硬条件。
  - 歌词只写“（剧本字幕）”。
  - 只出 JSON。
- **各节点要的 JSON 形状**：见 `buildPrompt()`，改提示词就是改方法，要升 skill 版本。
- **报错**：每种错误都有中文提示，比如没授权、太频繁、格式不对、太长。

## 八、自检（`tests/`）

```
cd ui-baseline/tests
python3 build.py              # 种子 + 假 Claude + 页面 → out/index.html
node test_page.js             # 27 条，全过才算通过；加 --shots 重拍 screenshots/
```

查的内容：

- 打开就停在 01E、默认是段核心页。
- 阶段卡描边跟着阶段卡和页签走（5 次）。
- 标注高亮。
- 选完三段后提示连读。
- 运行下一步三次跑到四张表，自动检查找出空拍和没去向的照片。
- 带漏洞重写会发出一次调用。
- 取舍后提示交接；下载文件名对；提示词格式对；删掉的提案不进提示词。
- 新标注、自己写、按要求重新生成都能用；回到旧版本能用。
- 页面没有报错；手机 400 宽四页都不横向滚动。

测试里的假 Claude（`mock.js`）按提示词里的固定句子分辨节点。改提示词句子时要一起改 mock。

## 九、已知限制（留给 CSP-UI-2 的）

- 真实 Claude 调用只在用户的 Claude 里能跑，沙盒里只用假数据测过。
- 一个项目只管一集；多集剧要开多个项目，还没有“全剧核心”一层。
- 质检（Q1）还在页面外做（Claude 用脚本查）；候选：加“质检”页签。
- 节拍表还没有“AI 风险”一列（方法 v0.1 第 13 节的暂定做法）。
- 版本记录只显示最近 12 版。

## 十、怎么升级（CSP-UI-1 → CSP-UI-2）

1. 项目里不改 `web/workbench.html` 的页签、模块、按钮名、配色；用户提的界面意见先记进 `方法论台账.md` 的 U 类。
2. 用户说“升级界面基线”时：
   - 把改动做进 `web/workbench.html`。
   - `tests/` 跟着改并全过，截图重拍。
   - 新写 `CSP-UI-2.md`：和上一版的差别表、用户原话。
   - 本文件留着当历史。
3. skill 升次版本，`SKILL.md` 第 10 节改成新基线编号，写进 `CHANGELOG.md`。
